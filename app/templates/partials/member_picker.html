{# Attach-picker body (issue #22) — the swap unit for search, paging, and ticking. THREE parts: the selected tray, the paged candidate list, the pager. ── How the selection survives search and paging ────────────────────────────── The tray is the selection; the candidate list is only a way to add to it. Every pick gets a chip, but a chip emits its hidden existing_*_ids input ONLY when its row is not on the current page. That split is what makes both directions work: • an off-page / off-filter pick is carried by its chip's hidden input, so searching, clearing the search, or paging away cannot lose it; • an on-page pick is carried by its checkbox alone, so UN-ticking the box really does drop it — a hidden input would resubmit the id and the tick would spring back. It also means an id is never submitted twice, so the count cannot double. Inputs: page (CandidatePage), picked (list[MemberCandidate]), picked_ids, page_ids (both sets of 'kind:id'), total_unfiltered, candidates_url, q. Rendered inside the caller's
