## 3. Region granularity — the open one (§V of the minutes)

The only design question the session failed to resolve. Recorded in detail because the shape of the answer determines whether it needs schema, logic, or nothing.

**The requirement.** Wendy: when a North America **suite** runs, each country runs individually underneath, and the grid should say what actually ran. Restated as a rule: "If I run a country-level profile, then I'd want to see the country in that table. If I'm running North Atlantic Hurricane, then I would want it to say North Atlantic" — i.e. **the most granular level the profile actually names**.

**Why it isn't free.** Cheryl complicated it correctly: for earthquake, North America genuinely *is* one model, so the right answer varies by peril; and the value is probably the profile's **top-level selection before expansion** — "when you set up the profile, you start at North America, and then you expand that, and then you would click US, Canada, or Mexico." She then hit the actual case: "I wonder for Hurricane would have pulled North Atlantic. I don't know."

**What the API offers.** Ben checked live:

| Source | Returns | Usable? |
|---|---|---|
| Analysis-details endpoint (what the grid uses today) | The **coarse** region (`North America`) | Wrong grain |
| `get regions by analysis result` → sub-regions | **~50 entries** for a US analysis | Too many to render |
| The analysis / profile **name** | The granularity, by convention | Text, and convention-dependent |

**Options on the table.**

- **(a) Threshold logic on sub-regions** — list them when few, "multiple (N)" above a cut-off. Cheryl proposed it; Ben accepted it works for the US, where sub-regions are cleanly organized, and warned it degrades elsewhere.
- **(b) Derive from the naming convention.** Wendy: "in theory, it's going to be in the name of the profile … if we follow the same naming convention, perhaps we can get it off of the name." Fragile — the name is free text.
- **(c) Show the coarse region and accept it.** Wendy's own fallback: "if it's easier to stick with North America, then we can live with that."
- **(d) Rejected outright:** a Workbench-maintained region dictionary. Ben: "What I definitely don't want to do is have to maintain some sort of dictionary in the workbench itself to say these states mean this country."

**Note the dependency chain.** Option (b) is the reason the name-length conversation happened at all (§4), and option (c) is only tolerable *because* D6 keeps the full 512-character name. If D6 were reversed, region would become a hard requirement rather than a nice-to-have. → **O20-4**.
