Execute Suite / Execute Template modal
Opens from the Portfolios header once ≥1 portfolio is checked. Same fragment for both entry points — kind=suite shows suites (expandable to their templates, deselectable, each with its own currency block); kind=template shows templates directly plus one currency block for the whole execution.

Revision 2, addressing review feedback:

1) Long lists — .exec-list gets the identical bounded/scrolling treatment as .entity-candidate-list (border, 320px max-height, its own scrollbar): a suite/template/treaty list of any length scrolls in place while the search field, currency blocks, and the Execute/Cancel footer stay fixed — the same answer the app already gives for a long "add existing EDM" candidate list.

2) Reusing existing styling — the previous draft got two things wrong and one thing genuinely new right: the modal shell is .modal-card.submission-entity-modal, the exact class submission_entity_add_modal.html already uses for a wide/scrollable modal; the treaty picker and the flat template list are the real .entity-candidate-list/.entity-candidate rows; every field (search, currency) is now the REAL .wf-field grid from app.css (label left, control right — the previous draft used the UI-preview scaffold's simplified stacked version, which isn't what the app actually renders); and the three currency pickers are the searchable .ta component (selectSearch() in app.js) — the same widget already driving Model Profile / Event Rate Scheme / Output Profile on the analysis template form, whose own code comment names currency/scheme/vintage as a planned future user. Genuinely new: only the suite's expandable row (.exec-row) and the thin .exec-currency wrapper around three ordinary fields.
