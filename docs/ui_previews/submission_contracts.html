Contracts on a submission
The CRM ID is the contract: its own treaty type, inception, expiration and Won / Lost / In Process status. The submission keeps the modeling work, the cedant, the client and one data vintage.
1 · New submission — three contracts entered

Name and cedant are the only required submission fields. Each contract row needs a CRM ID, treaty type and inception; expiration fills as inception plus one year minus a day when left blank; status starts In Process. A new row opens with the previous row's dates. Treaty year filled itself from the data vintage.

No new column and no pills. CRM ID keeps its "first + N more" cell; Treaty types uses the same pattern. Inception is the latest contract inception. Contract status is not a column: the Contract status filter answers "which deals have a Won contract", and the deal card shows the status per contract. A deal with no contract shows dashes and sorts by its creation date.

What leaves the page

The Treaty group and the Term group of the 9/18 card (their facts are now per contract); the CRM band and its "Make dates the same" button; the Term pencil and the deal-level dates editor; the Submission status select in the Status editor (the Status editor changes Modeling status only). On the create form: the submission-level Treaty type, Inception and Expiration fields. New CSS: .contract-band, .contract-table, .contract-row and its editor variant.
