State 1 · populated — every status a run can show

Status is derived from the analysis's latest tracked job, not a stored label (T-07): freshly-inserted rows with no job yet read Submitting…; a live Risk Modeler job shows its own status (Queued, Running); a submission that never reached Risk Modeler reads Failed to submit · attempt n/max and keeps retrying until the configured maximum (FR-010); a finished run backfills its settings into the expanded row (FR-009); a run Risk Modeler executed and failed, or one cancelled directly in Risk Modeler (P-13), both show their reason inline — visible without expanding (FR-011).

The expanded settings grid is the identical field set and derivation broker analyses already show (analysis_service.AnalysisSettings/_to_display, shared via partials/_analysis_metadata_fields.html so the two views can't drift) — nothing new is guessed here. Term and PLA render blank in this example because their Risk Modeler field names are still unconfirmed (docs/IRP_INTEGRATION_FOLLOWUPS.md §9); no string-matching against the event-rate scheme happens anywhere — Engine type (DLM/HD) and Analysis type/mode come straight from Risk Modeler's own documented fields.
