State 1 · populated — grouped by status, failures on top (design 18 D4/D5)

Rows are partitioned into three fixed groups — Failed (run failures and failed-to-submit rows), In progress, Ready — date-descending within each group. The header gains a status filter (server-rendered selected, survives the 3s poll) and a Delete button that enables when terminal rows are ticked (P-19): the delete cascades to Risk Modeler synchronously, then soft-deletes locally. Only terminal rows get a checkbox — a row whose job just FINISHED but whose irp_id backfill hasn't landed yet does not (deleting in that window would orphan the RM analysis). Names follow the CRE_{portfolio}_{template} rule with _2, _3… rerun suffixes (P-05/P-10 as amended); a backfilled row links out to the analysis in Risk Modeler (RM ↗). New columns: Template and Submitted (localized).
