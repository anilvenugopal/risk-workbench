Notes for the reviewer
  • Row click toggles the checkbox. Unlike the EDM Library, a row here is not a link — there is nothing to open yet.
  • Counts come from Risk Modeler's own metrics (metrics.portfolioCount / treatyCount on the exposures response), so the analyst can tell a real book from a scratch database before syncing. Zero renders as —.
  • The Risk Modeler link is a plain navigation link, never an API call (Article 11), built from RISK_MODELER_TENANT_NAME + the registrable domain of RISK_MODELER_BASE_URL by the same helper the EDM detail page already uses for its treaties link. RM addresses the datasource by name, so for a duplicated name the link lands on whichever one RM picks — which is why the exposureId column stays. The column is empty when no tenant name is configured (api-key deployments).
  • Status is status on Risk Modeler's exposures response, verbatim — not the workbench's irp_edm.status, which is ready for every synced row. READY is the only value observed in the sandbox (all 6 EDMs in probes/results/a0_edms.json); Moody's documents status as a filterable string but never lists its values, so the chip renders whatever arrives and only READY gets the green treatment. PROCESSING in state 1 is a placeholder for "some other value", not a value anyone has seen.
  • 50 rows per page, matching submission_service.PAGE_SIZE, with the .pager markup the submissions list already uses. Paging happens after the diff, in memory — asking Risk Modeler for 50 rows and then removing the already-synced ones would hand back ragged pages, and on a tenant whose EDMs are mostly synced the early pages would arrive empty while later ones were full. So the Risk Modeler walk is the same length whether or not the page is paged; paging is about the table, not the call.
  • Ticks do not survive a page change, and the hint next to the pager says so. Sync applies to the page in front of you: submit, land back on the same page with those rows gone, then move on. Unlike the submissions pager these links are plain navigations rather than hx-get swaps, since changing pages abandons the form either way. Carrying selections across pages needs an Alpine store — not built, tell me if bulk-adopting across pages is a real workflow.
  • The search narrows before the paging, so total and the page count describe the filtered list. Re-searching drops you on page 1 (the filter form carries no page input, as in submissions.html:84).
  • No 3-second polling on this page. Each render is one live Risk Modeler call; a self-poll would turn one page view into a call stream. The newly synced rows are watched on /edms, which polls the local table only.
  • Deviation from the approved plan: the plan redirected to /edms after Sync. State 5 instead returns to this page with a banner, because it is the only place the "already taken by another analyst" skip can be reported, and the analyst can carry on syncing. The banner links to the library. Say the word if you prefer the plain redirect.
