Group analyses: the three-screen compose dialog
Opens from the Group button in the merged analyses grid once two or more rows are ticked. Replaces the single-scroll dialog with three screens in one shell 1080px wide (a new .modal-card--group width on the .modal-card--wide shell). Analysis and scheme names run long, so names wrap onto more lines instead of truncating, and every name carries a hover tooltip (the title attribute the pick-list already uses). Everything below the header is existing CSS except the step indicator, the partition table, and the notice blocks, which are marked net-new in the source.
1 · MembersPick two or more finished analyses; name the group.Next runs the inspection.
2 · InspectionEvent-rate scheme table by peril / region / model version; treaty mismatches.Next needs every conflicting row chosen. Treaty mismatches never block.
3 · SettingsSummary, currency block, Propagate detailed output, simulation count when the group is a PLT.Group submits.
Screen 1 · Members — three rows arrived pre-checked from the grid, name prefilled

The whole submission-scoped pick-list, including the rows ticked in the grid. The search box filters by name as the analyst types (client-side, no request). Running and failed analyses are not listed. The count under the list is what Next gates on: two or more members and a non-empty name.

Screen 2 · Inspection — one scheme mismatch (one row chosen, one still open) and one treaty mismatch

One row per peril / region / model-version partition. The Members column lists the analyses in that partition by name only, wrapping long names; scheme ids, PET ids, and period counts are not shown. The scheme column is the widest so a full scheme name fits on one or two lines. A native dropdown cannot wrap its selected text, so the select carries the chosen scheme as its tooltip and the open list shows the full names. A mismatched row's dropdown offers only the members' schemes, each option naming who uses it; it starts empty in the warning style and no default is preselected. A consistent row shows the scheme that will be used. Next enables when every open dropdown has a choice. Treaty mismatches are listed underneath and never block.

Screen 3 · Settings — PLT group

The left column restates what will be grouped: name and output type, then the members, then the inspection outcome (schemes chosen and the treaty mismatch count). The right column is the settings: the currency block reused from the execute modal, Propagate detailed output ON, and Simulation count prefilled with the largest member PLT length. For an ELT group the simulation count field is absent and 1 is sent. Group submits; a 422 re-renders this screen with the errors at the top in the existing .modal-error style.
