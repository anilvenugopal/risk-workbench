Analysis comparison — pairwise cart, dedicated page
Iteration 10 (branch 013). Design: notes 19 §6 (D17–D20) and 20 §6.5 (D16/D17); PRD §17.3. Compare is its own action beside View on the merged analyses table (both entry points). A modal collects strictly pairwise selections into a cart — first picked = base = first column, percent change follows that order (D19). Pairs come from the table at hand; the modal offers only analyses with retrieved results, and a pair must share a run currency (D17 — blocked, never converted). The comparison opens on a dedicated page in a new browser tab under the dedicated results page's rules (breadcrumbs, tab title). Perspective and the single EP type apply screen-wide, never per pair.
1 · Entry — Compare beside View on the merged table's summary bar

The section summary bar (analyses_merged_section.html) gains a Compare button. Unlike View it needs no prior selection — picking pairs happens in the modal — so it is enabled whenever two or more analyses have results.

3 · The comparison page — two pairs, new tab

The dedicated results page's toolbar, verbatim — Perspective (Pre-Cat Net default), EP type (one at a time), Units, Copy table — applying screen-wide to every pair (D20 + 8/26 D11). Each pair is three columns: base, second, % Chg — labelled with analysis names only, no row-header column, no per-pair label (D20). Percent change follows selection order: pair 1 reads (broker − base) / base. The header sub-line carries currency and the engine/model version each side ran (note 18 O18-10 / spec 011 FR-021). AAL and Std dev sit below the curve, outside the EP-type selection, each with its own percent change. Breadcrumbs and tab title follow the View rules (D21/D22).
