A member mid-import or already on its way out (importing / delete_pending / deleted) gets no ✕ at all — remove_member's UPDATE predicate would refuse it, and a button guaranteed to 422 is worse than no button. A pending_import or error member keeps its ✕ on purpose: it cannot be re-attached until it is ready, so removing that control would leave Delete — which removes every member from Risk Modeler — as its only exit. Clicking the ✕ does not toggle the row: that needs preventDefault, because opening the row is <summary>'s default action, not a bubbling listener. Cost: it is type="button" + hx-post rather than a nested form, so this one control has no no-JS fallback.
8 — Remove ≠ Delete (the confirm copy carries the difference)
confirm copy
🔵 Remove from package → “Remove ACME_RE_2026 from this package? It stays in Risk Modeler and returns to the standalone library — anything already applied to it is not undone.”
🔵 Remove from package, only live member → “This is the only member — removing it also deletes this package. Nothing is removed from Risk Modeler. Continue?”
🔴 Delete → “Delete this package? Every member EDM/RDM is removed from Risk Modeler — including any that were imported standalone and later attached. To keep one, remove it from the package first.”
