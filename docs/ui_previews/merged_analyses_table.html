Merged analyses table — one column set, two pages
The EDM detail page's Analyses and Broker analyses sections become one table (FR-009), and the submission Results section renders the same partial over a wider row set. Type, Peril, Region, Engine and Currency all come from AnalysisSettings — the display model own and broker rows already share — so the two origins fill the same columns. Analysis names carry no sub-line. The Risk Modeler link is its own column at the end, following the EDM/RDM tables on the submission page, so it is not a misclick trap next to the name. No status sections: the status filter already does that. No perspective or units controls: the AAL column is Gross in millions, and switching belongs on the dedicated results page where analyses sit side by side.

1 · EDM detail page — the merged Analyses section

Own rows run straight down, newest first, red chip where a run failed with its reason inline. RDM group rows follow, expanding to their broker analyses (05 §1 relocated into the one table, not retired). Controls stay on the section summary line where the status filter and Delete already live — Copy table and View join them. Expanding a row gives two columns. On the left, the source line (portfolio or RDM, analysis id) then two named groups — Metadata (engine version, analysis type, peril, subperil, framework, event rate scheme, analysis template) and Analysis settings (currency code/scheme/vintage, min loss threshold, franchise deductible, unrecognized construction and occupancy). On the right, the condensed results: both EP types at the 6 return periods, perspective toggle in the row (FR-011). The columns stack when the row is too narrow to hold both. Group values wrap to as many lines as they need — the event rate scheme name below is a real-length one — and every value carries a title, as does each summary cell that truncates.

Four states, one cell, no extra column and no perspective control on the table. A retrieval that failed keeps the run reading Finished (SC-005) and puts its reason on the same line the run's own failure reason uses.

Where the expanded-row fields come from
Metadata reads from the Risk Modeler analysis payload and fills in for both origins: engineVersion/engineType, analysisType, peril, subperil, analysisFramework (the Framework field — the workbench parses it into analysis_mode today and needs its own field), plus the analysis template, which only workbench runs have.
Analysis settings are template values, and Risk Modeler does not return them. Min loss threshold, franchise deductible and unrecognized construction/occupancy live on analysis_template, and currency scheme + vintage are chosen at submit time (009 P-11). Own rows read them from the record of the run; broker rows read not returned for all four and carry only currencyCode. Event rate scheme is the same story in reverse: documented on neither payload, so it shows for own runs and stays blank for broker ones.
Submitted is rendered in the browser. The column shows date, time to the second, and AM/PM, in the reader's own zone — 2026-08-24 2:02:37 PM. The server writes UTC into <time datetime="…Z"> and a small script formats it with toLocaleString, because the server has no way to know the reader's zone. The column is 180px so nothing clips at a two-digit hour.
Two additions to BrokerAnalysis. rm_url, built from the underlying analysis id rather than the user-facing one (O19-3), and createDate — it is documented on the analysis payload, so the Submitted column can carry the broker's own run date instead of the — the broker rows show here. Confirm both.
