Owner is pre-filled with the signed-in analyst, same convention as /submissions — clearing the chip is the same as picking "Any owner" (sends owner=any). A job whose EDM/RDM belongs to no submission (e.g. the batch-execution row) still shows here because no submission-scoped filter is set; it would drop out the moment one is. Each submission name opens /submissions/{id} in a new tab. Clicking a column header sorts by it (D15 convention); clicking the same header again flips direction. A Dead row (running, but its worker stopped heartbeating) offers Cancel; a Failed row offers both Resubmit and Cancel — picking either forecloses the other.

Clicking Cancel on a Dead row and the poller's reconciler reclaiming that same row are the same race as claim-vs-cancel on a pending row: whichever UPDATE lands first wins, the other matches zero rows and is a silent no-op — no error toast, the row just re-renders showing whatever it actually became. Here the reconciler won, so the row is back to Pending (with its own fresh Cancel available) instead of Cancelled.
