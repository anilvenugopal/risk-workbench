To add a page: add a node to app/nav/manifest.py, a handler in a router, and a template. To add a background job type: see "Adding a new job type" in docs/WORKER_ARCHITECTURE.md.

Testing

TierDirectoryNeedsCommand
Unittests/unitNothinguv run pytest tests/unit
SQL Servertests/sqlserverODBC Driver 18 and a running SQL Servermake test-sql (Docker) or make wsl-test-sql (WSL2)
Risk Modeler sandboxtests/irpRisk Modeler credentials in the environmentuv run pytest tests/irp --run-irp, from make shell
  • Always run tests with uv run pytest. A bare pytest fails with ModuleNotFoundError because the dependencies are in the uv environment.
  • Tests in tests/sqlserver and tests/irp are skipped unless --run-sqlserver or --run-irp is passed (tests/conftest.py).
  • The SQL Server tier fails from a Windows host shell even when SQL Server is up, because the ODBC driver and MSSQL_* variables live in linux-box or the WSL2 shell. If tests/sqlserver/test_connectivity.py fails, the environment is wrong, not the code.

Unit tests use SQLite. The iteration1_db and iteration2_db fixtures in tests/conftest.py build the schema from tests/iteration1_mirror.py in memory, seed the kind tables, and call register_engine("WORKBENCH", engine). The loss_db fixture does the same for LOSS from tests/loss_mirror.py. No unit test needs Redis or Risk Modeler: no Dramatiq sender is configured, and the gateway is replaced with a fake.

tests/unit/test_architecture_guards.py enforces several constitution rules by reading the source: no poll_*_to_completion calls, no gateway calls from routers, no DATABRIDGE read on the request path, and SQL only through db/ in the export modules.

CI is .github/workflows/ci.yml. It runs on pull requests to main, pushes to main, and manual dispatch, as two parallel jobs:

JobSteps
Unit testsuv sync --frozen, then make wsl-test.
SQL Server integration testsStarts a SQL Server 2022 service container, installs ODBC Driver 18, runs uv sync --frozen, copies infra/.env.example to infra/.env, then make wsl-db-bootstrap, wsl-db-migrate, wsl-db-seed, and wsl-test-sql.

The Risk Modeler sandbox tier is not in CI. CI never creates the loss tables; the loss tests in tests/sqlserver apply db/bootstrap/loss_dev_mirror.sql themselves.

Report test results by tier and count, for example "unit tier, <n> passed; SQL Server tier not run". A change that adds tests/sqlserver tests is unverified until someone runs that tier.

Conventions

AGENTS.md is the one source of rules for changing the code. It applies to people and to coding agents. Its main rules:

  • Make the smallest change that meets the requirement. No code for hypothetical needs, no abstraction with one caller, no unrelated clean-up.
  • Comments explain constraints the code cannot show. They do not narrate the code or record its history; history goes in the feature's research.md.
  • Write plainly: name the real table, route, or file; lead with the answer; keep descriptions proportional to the change. The section lists banned words.
  • Commit subjects are at most 72 characters; the body says why. No AI attribution lines in commits or pull requests.
  • Do not start, stop, or rebuild the developer's containers from an agent.
  • Show a rendered HTML preview before building a screen with new layout, and build one user story at a time. See page 6.

Lint and format with ruff: make lint and make format (Docker), or uv run ruff check . from any shell. The settings are in pyproject.toml (line length 100, Python 3.12).
