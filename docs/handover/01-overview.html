1. Overview

What the Workbench does

The Risk Analysis Workbench is a web application for CIC's reinsurance catastrophe-modeling analysts. It drives Moody's Risk Modeler through its API, so an analyst can import exposure, run analyses, review results, and export loss tables without working in the Risk Modeler UI.

Two roles use it, both stored in role_kind:

  • analyst: works submissions end to end.
  • admin: everything an analyst can do, plus user administration and creating, editing, and deleting analysis templates and template suites.

Every authenticated user sees every submission. There is no row-level security.

The round trip for one submission:

StepWhat the analyst doesWhat the Workbench does
1Creates a submission with its cedant, client, data vintage, and contracts.Writes submission and contract rows.
2Picks an EDM or RDM file from the shared drive, or links an EDM that already exists in Risk Modeler.The upload_edm or upload_rdm worker submits the Risk Modeler import job. The poller tracks it, then the backfill_edm_detail or backfill_rdm_analyses worker reads the EDM's portfolios and exposure, or the RDM's analyses.
3Optionally splits a portfolio into breakouts, and optionally runs a hazard lookup (GeoHaz).The run_breakout_* workers create the portfolios in Risk Modeler. The run_geohaz worker submits the hazard lookup job.
4Picks portfolios, a template suite or a single template, and the currency, then runs the analyses.The execute_analysis_batch worker submits one Risk Modeler analysis job per portfolio and template. When a job finishes, the poller enqueues finalize_analysis, which enqueues retrieve_analysis_results to read the EP, AAL, and statistics.
5Reviews and compares results, and groups finished analyses.The submit_grouping worker submits the grouping job. A finished group is treated as an analysis.
6Exports finished analyses to CIC's loss repository.submit_results_export asks Risk Modeler for the event loss table, stage_results_export downloads it into the loss repository's stage schema, and load_results_export loads it into dbo.Data, dbo.RMSELT, and dbo.RMS_HistoricalRDS.

How the request path, workers, and poller divide the work is on page 2. The product requirements are in docs/PRD.md.

Glossary

TermMeaningWhere it lives
SubmissionOne cedant's modeling project, and the top-level container in the Workbench. It holds the cedant, client, data vintage, treaty year, assigned analyst, and modeling status (Active, Completed, Cancelled). EDMs and RDMs are linked to it, not copied into it.submission, submission_edm, submission_rdm
Contract / CRM IDOne contract from CIC's CRM, identified by its CRM ID. A submission has zero or more contracts. Each contract has its own treaty type, inception, expiration, and contract status (Won, Lost, Open).contract
EDMExposure Data Module: a Moody's exposure database, usually a broker's .bak or .mdf file, imported into Risk Modeler.irp_edm
RDMResults Data Module: a Moody's results database, usually the broker's own analyses, imported into Risk Modeler for comparison.irp_rdm
PortfolioA named set of accounts inside an EDM. Risk Modeler runs analyses against portfolios, not against EDMs.irp_portfolio
BreakoutA portfolio created by filtering a source portfolio by line of business, state, country, peril, or a custom grouping of those values. One breakout run creates one portfolio per value or group.breakout_group, irp_portfolio
AnalysisOne Risk Modeler analysis. It is either run by the Workbench against a portfolio, or imported from an RDM (rdm_id is set). A group is also an analysis (is_group is set).irp_analysis
TemplateAn analysis template: one analysis definition made of a model profile, an output profile, an event rate scheme, and analysis settings. A template stores no currency; the analyst picks the currency when running it.analysis_template
SuiteA template suite: a named, unordered set of templates that run together.template_suite, template_suite_item
GroupingCombining finished analyses or groups of one submission into one group analysis in Risk Modeler.irp_analysis, irp_analysis_group_member
GeoHazHazard lookup on a portfolio. It is optional and does not re-geocode. Every launch sends the hazard data version in HAZARD_DATA_VERSION.irp_job with type geohaz
Treaty / TYA treaty is a reinsurance treaty stored in an EDM. TY is the treaty-level export: one loaded data set per treaty. TY is an output level, not a financial perspective.irp_treaty; TY in app/config.py
Event rate schemeA Risk Modeler set of event rates that an analysis uses. Required for DLM model profiles, optional for HD. Templates reference it by its Risk Modeler id, because scheme names repeat across peril and region.irp_event_rate_scheme; analysis_template.event_rate_scheme_irp_id
ExportLoading the event loss table of one or more finished analyses, at one perspective (GU, GR, RL, RP, or TY), into CIC's loss repository.stage.rwb_loss_result_manifest in the loss database
Loss repositoryCIC's SQL Server database of loss sets, CRE_Trial_ELT_Repository. The Workbench writes to it only through its own stage schema. The dev copy is rwb_loss.See page 3

The longer product glossary is section 1.4 of docs/PRD.md. The table definitions are in docs/DATA_MODEL.md.
