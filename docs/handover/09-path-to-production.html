9. Path to production

The state of the deployed environment is as the development team reported it on 2026-10-01. Every claim about the code was checked against it on the same day. The Owner column is for the handover call.

Blockers

#ItemState todayWhat is neededOwner
B1nginx does not serve the app on port 80In the deployed environment the app cannot be reached through nginx on port 80. The cause has not been investigated. uvicorn listens on 0.0.0.0:8000, so the app can be reached on port 8000 without nginx. The last step of rhel9-ssh-deploy.sh calls http://127.0.0.1:80/api/health, so it fails while nginx is broken.Decide whether production uses nginx. If it does, find and fix the cause. HTTPS (B12) depends on the answer.
B2Deployment is manualThe code is copied onto the server by hand. No CD process runs. The scripts exist: rhel9-ssh-deploy.sh pushes the code with rsync over SSH, rhel9-pull-code.sh pulls it from GitHub on the server, and rhel9-app-install.sh installs it. See page 8.CIC builds the CD process, and it can call these scripts. The push needs SSH from the CD runner to the server; the pull needs GitHub access from the server.
B3Dependencies cannot be installedThe server may not connect to PyPI, so rhel9-app-install.sh fails at pip install --require-hashes -r requirements.txt.CIC hosts the Python packages in a CIC-owned Artifactory. Then point pip on the server at it, with PIP_INDEX_URL or /etc/pip.conf; the install script sets no index of its own. The hashes in requirements.txt still check every package, so the Artifactory must serve the same files as PyPI.
B4The shared drive is mounted at the wrong levelThe shared drive is mounted on the server at /Workbench. The team wants a higher-level directory mounted.CIC mounts the higher-level directory on the server. Then set SHARED_DRIVE_ROOT in infra/.env to the new mount point, and stop and start the app.
B5The app writes to a trial loss repositoryThe LOSS connection points at CRE_Trial_ELT_Repository, a trial repository, not CIC's real loss repository. dbo.Client and dbo.Lookup_RMS_HistoricalRDS in it were loaded by hand.Set MSSQL_LOSS_* in infra/.env to the production loss repository. A CIC DBA installs db/bootstrap/loss_schema.sql in it. Run specs/014-results-export/cic-reference/validate_loss_repo_server.sql against it.
B6Logs are not collected, and a start erases themEach process writes its log to /var/lib/risk-workbench/ on the server, and nothing picks them up. rhel9-start.sh redirects each log with >, so every start empties it, including the lines that show why a process died (issue #173). Nothing rotates them. See page 7.Fix issue #173: append with >> and add rotation. Ship the logs to a log aggregator, following CIC's standard approach. LOG_FORMAT=json writes one JSON object per line.
B7Entra sign-in is not set upPassword sign-in is the only sign-in that works in the deployed environment.Register the app in Entra and set the ENTRA_* variables, following docs/ENTRA_SETUP.md. This needs an https redirect URI (B12). Then set AUTH_MODE=oidc and fix B13.
B8Export archives are not written to the shared driveEach export keeps the Risk Modeler archive under EXPORT_ARCHIVE_DIR and unzips it into EXPORT_STAGING_DIR, both set in infra/.env. The app never creates either directory; the stage step fails an analysis when one is missing. cinreadmd has read access to the shared drive only, so the archives cannot be written there today.Archives are written to a location on the mounted shared drive, still to be chosen; it may sit under the higher-level mount in B4. CIC creates that directory and gives cinreadmd, the account that runs the app (B10), write access to it. Then set EXPORT_ARCHIVE_DIR in infra/.env to that directory, and stop and start the app. EXPORT_STAGING_DIR stays a local directory on the app server, emptied after each analysis. Nothing deletes archives; sweep-export-archives.sh runs only by hand (runbook on page 8). If CIC sets a retention period, schedule the sweep; an archive is the only copy of the original ExpValue and StdDev of the rows the load procedure corrects.
B9The app does not start after a server restartrhel9-start.sh starts uvicorn, the Dramatiq workers, the poller, and Valkey with nohup. Nothing starts them after a reboot or restarts one that dies. Only nginx is a systemd service. The team decided not to write systemd units for the other four.Give the team that maintains and restarts the Linux server rhel9-start.sh and the "After a server restart" steps in the runbook on page 8. That team runs the steps after every restart.
B10Separate deployment and run accountscinreadmd deploys the code and runs the app. Every script takes one account, DEPLOY_USER.One account deploys and a second runs the app; the split is in Accounts on page 8. Infra creates the accounts. rhel9-setup.sh gives DEPLOY_USER both /rms and /var/lib/risk-workbench, so it needs a second account setting for the run account.
B11The lower environment is being builtCIC is creating a lower environment now. The existing server becomes production. Design note 25 (D8, O25-6) records that the loss repository had no lower environment and that CIC said it would create one.The new server needs the one-time setup on page 8, its own infra/.env and Workbench database, and the firewall rules and Data Bridge allowlist entry in Outbound connections. To confirm: whether the lower environment has its own loss repository and Risk Modeler tenant.
B12HTTPSHTTPS is wanted in production. deploy/nginx/site.conf listens on port 80 only, and analysts reach uvicorn over HTTP on port 8000 (B1). Entra accepts an http redirect URI only for localhost, so production sign-in (B7) needs HTTPS.The steps in Enabling HTTPS on page 8: a hostname and certificate, a TLS server block in site.conf, an inbound firewall rule for port 443, uvicorn bound to 127.0.0.1, and APP_ENV and ENTRA_REDIRECT_URI set. Depends on B1.
B13Password sign-in is not switched off by AUTH_MODEPOST /auth/login in app/routers/auth.py accepts a password whatever AUTH_MODE is set to; AUTH_MODE=oidc only hides the form. AGENTS.md says the password path must never be reachable in production.Make POST /auth/login refuse when AUTH_MODE=oidc, and set AUTH_MODE=oidc in production.
