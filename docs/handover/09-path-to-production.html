9. Path to production

The state of the deployed environment is as the development team reported it on 2026-10-01. Every claim about the code was checked against it on the same day. The Owner column is for the handover call.

Blockers

#ItemState todayWhat is neededOwner
B1nginx does not serve the app on port 80In the deployed environment the app cannot be reached through nginx on port 80. The cause has not been investigated. uvicorn listens on 0.0.0.0:8000, so the app can be reached on port 8000 without nginx. The last step of rhel9-ssh-deploy.sh calls http://127.0.0.1:80/api/health, so it fails while nginx is broken.Decide whether production uses nginx. If it does, find and fix the cause. HTTPS (B12) depends on the answer.
B2Deployment is manualThe code is copied onto the server by hand. No CD process runs. The scripts exist: rhel9-ssh-deploy.sh pushes the code with rsync over SSH, rhel9-pull-code.sh pulls it from GitHub on the server, and rhel9-app-install.sh installs it. See page 8.CIC builds the CD process, and it can call these scripts. The push needs SSH from the CD runner to the server; the pull needs GitHub access from the server.
B3Dependencies cannot be installedThe server may not connect to PyPI, so rhel9-app-install.sh fails at pip install --require-hashes -r requirements.txt.CIC hosts the Python packages in a CIC-owned Artifactory. Then point pip on the server at it, with PIP_INDEX_URL or /etc/pip.conf; the install script sets no index of its own. The hashes in requirements.txt still check every package, so the Artifactory must serve the same files as PyPI.
B4The shared drive is mounted at the wrong levelThe shared drive is mounted on the server at /Workbench. The team wants a higher-level directory mounted.CIC mounts the higher-level directory on the server. Then set SHARED_DRIVE_ROOT in infra/.env to the new mount point, and stop and start the app.
B5The app writes to a trial loss repositoryThe LOSS connection points at CRE_Trial_ELT_Repository, a trial repository, not CIC's real loss repository. dbo.Client and dbo.Lookup_RMS_HistoricalRDS in it were loaded by hand.CIC names the production loss repository and its server, and creates the LOSS login and grants (C4). A CIC DBA installs db/bootstrap/loss_schema.sql in it (C5). Set MSSQL_LOSS_* in infra/.env. Run the server check script against it (C1, C2, C3, C7).
B6Logs are not collectedEach process writes its log to /var/lib/risk-workbench/ on the server, and nothing picks them up. rhel9-start.sh truncates each log at every start (it redirects with >), and nothing rotates them. See page 7.Ship the logs to a log aggregator, following CIC's standard approach. Add rotation, and change rhel9-start.sh to append so a restart does not lose lines before they are shipped. LOG_FORMAT=json writes one JSON object per line.
B7Entra sign-in is not set upPassword sign-in is the only sign-in that works in the deployed environment.Register the app in Entra and set the ENTRA_* variables, following docs/ENTRA_SETUP.md. This needs an https redirect URI (B12). Then set AUTH_MODE=oidc and fix B13.
B8Export files are never cleaned upExports write archives to EXPORT_ARCHIVE_DIR and extracted files to EXPORT_STAGING_DIR, both set in infra/.env. infra/scripts/sweep-export-archives.sh deletes old ones, but only when someone runs it by hand. The number of files grows with every export.Schedule the sweep with cron or CIC's scheduler, for both directories. CIC chooses the retention age: an archive is the only copy of the original ExpValue and StdDev of the rows the load procedure corrects. See the runbook on page 8.
B9systemd units for uvicorn, the Dramatiq workers, the poller, and ValkeyNone exist. rhel9-start.sh starts all four with nohup as the deployment account, so nothing restarts a process that dies or brings the app back after a reboot. Only nginx is a systemd service.Write one unit per process (one per queue for the workers, using python -m app.workers.queues), owned by infra, and switch the start and stop scripts to systemctl. The open item is in RHEL9_DEPLOYMENT.md.
B10A dedicated service accountEvery script takes DEPLOY_USER; every example uses the personal account cinreadm.Infra creates a non-personal account that owns /rms and runs the processes; the systemd units name it.
B11No lower environmentThe repo describes one RHEL9 target. Design note 25 (D8, O25-6) records that the loss repository has no lower environment and that CIC said it would create one.A test environment for the app and the loss repository, so a release can be tried before production.
B12HTTPSdeploy/nginx/site.conf listens on port 80 only. Entra accepts an http redirect URI only for localhost, so production sign-in needs an https ENTRA_REDIRECT_URI.A certificate on nginx or a TLS-terminating load balancer, and the production redirect URI registered in Entra.
B13Password sign-in is not switched off by AUTH_MODEPOST /auth/login in app/routers/auth.py accepts a password whatever AUTH_MODE is set to; AUTH_MODE=oidc only hides the form. AGENTS.md says the password path must never be reachable in production.Make POST /auth/login refuse when AUTH_MODE=oidc, and set AUTH_MODE=oidc in production.
