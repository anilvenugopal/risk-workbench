B1systemd units for uvicorn, the Dramatiq workers, the poller, and ValkeyNone exist. rhel9-start.sh starts all four with nohup as the deployment account, so nothing restarts a process that dies or brings the app back after a reboot. B2A dedicated service accountEvery script takes DEPLOY_USER; every example uses the personal account cinreadm.Infra creates a non-personal account that owns /rms and runs the processes; the systemd units name it.
B3How code reaches the serverThe push deploy exists: rhel9-ssh-deploy.sh sends the code with rsync over SSH and runs pip install on the server.Infra confirms that a CI runner or developer machine may SSH to the server, and that the server can reach PyPI or the packages are staged on it.
B4No lower environmentThe repo describes one RHEL9 target. Design note 25 (D8, O25-6) records that the loss repository has no lower environment and that CIC said it would create one.A test environment for the app and the loss repository, so a release can be tried before production.

B6Password sign-in is not switched off by AUTH_MODEPOST /auth/login in app/routers/auth.py accepts a password whatever AUTH_MODE is set to; AUTH_MODE=oidc only hides the form. AGENTS.md says the password path must never be reachable in production.Make POST /auth/login refuse when AUTH_MODE=oidc, and set AUTH_MODE=oidc in production.
