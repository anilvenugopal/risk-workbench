3. Data

The databases

The app names each database by a connection name. The db/ package builds the connection from the env vars MSSQL_<NAME>_SERVER, _PORT (default 1433), _DATABASE, _USER, _PASSWORD, and _AUTH_TYPE (SQL by default, or WINDOWS for Kerberos). The full variable list is on page 7.

Three status columns are plain text because they copy Risk Modeler's own values: irp_job.status, irp_edm.status, and irp_rdm.status.

How to change a kind table's values is on page 7.

Submission status is event-sourced. It is the only event-sourced status.

  • submission.status_code holds the current value. New submissions start at ACTIVE.
  • submission_status_event holds every change: submission_id, status_code, reason, at, inserted_by.
  • set_status() in app/services/submission_service.py writes both in one transaction. It opens get_connection("WORKBENCH"), calls conn.begin(), updates submission with WHERE id = :id AND updated_at = :expected, raises ConcurrencyConflict if no row changed, and inserts the event.
  • create_submission() in the same file writes the first ACTIVE event with the submission.

Every other status, including contract.contract_status_code, rwb_job.status_code, and irp_analysis.status_code, is updated in place.

Data access

All SQL goes through the db/ package. It uses SQLAlchemy Core for connection pools only; there is no ORM. The package is described in db/README.md.

FunctionUse
db.execute(sql, params=None, connection="WORKBENCH")The default. Runs SQL with bound :name parameters and returns list[dict]. Every query that touches a user-supplied value uses it.
db.execute_one, db.execute_scalar, db.execute_command, db.execute_procedureVariants of the same bound-parameter path: one row, one value, one statement that returns a row count, and a stored procedure call.
db.get_connection(name)A context manager that yields a pooled connection. Use it with conn.begin() when two statements must commit together.
db.register_engine(name, engine)Replaces the engine for a connection name. The unit tests use it to point WORKBENCH and LOSS at SQLite.
db.elt.upload_parquetBulk-inserts a Parquet file. The export worker uses it to load stage.rwb_loss_result_elt_data.
from db.scripts import execute_script_fileThe trusted-script path: substitutes {{ param }} into the SQL text, splits on GO, and returns DataFrames. It is not exported from db, so every use is an explicit import. The only caller is infra/scripts/bootstrap_loss.py.

All connections share one pool setting, MSSQL_POOL_SIZE and its siblings, read in db/connection.py; there are no per-connection pool settings. Defaults are on page 7.

Migrations

  • Alembic manages WORKBENCH only. alembic/env.py builds the database URL from the same MSSQL_WORKBENCH_* variables as the app.
  • alembic/env.py has no model metadata, so --autogenerate does not work. Write upgrade() and downgrade() by hand with op.*.
  • alembic/versions/0001_initial.py is the base revision. It is frozen; never edit it.
  • Revision ids are four-digit numbers. The head is 0003, so the next is 0004.
  • Any kind-table rows a change needs go in the same revision as the table or column that uses them.
RevisionChange
0001The full schema and every kind-table seed row.
0002Adds model_profile_irp_id, output_profile_irp_id, and event_rate_scheme_irp_id to analysis_template.
0003Adds irp_job.progress.
CommandWhat it does

uv run alembic headsShows the head revisions. main must have exactly one.
make db-migrate (Docker) or make wsl-db-migrate (WSL2)Runs alembic upgrade head.

tests/iteration1_mirror.py is a SQLite copy of the Workbench schema (ITERATION1_SCHEMA to ITERATION4_SCHEMA) plus the kind-table seed lists (*_SEED). The unit tests build it in memory. A revision that changes a mirrored table or adds a kind-table row must update the mirror in the same commit. tests/sqlserver/test_schema_drift.py compares the mirror's columns with the real schema; it does not check seed rows. tests/loss_mirror.py does the same for the loss database.

The full procedure is under "Schema Changes" in AGENTS.md.
