10. Deployment checklist

From an empty RHEL9 server to the Workbench running. Commands: RHEL9_QUICKSTART.md. "To fill in" marks a value CIC supplies.

1. Server

  • A RHEL9 server. To fill in: hostname and IP address.

  • An empty Workbench database on CIC's SQL Server, created by a CIC DBA. To fill in: its name.
  • The stage schema installed in CIC's loss repository from db/bootstrap/loss_schema.sql, by a CIC DBA with db_owner (page 3).

5. Directories

  • The broker file share mounted on the server, readable by cinreadmd.
  • EXPORT_ARCHIVE_DIR and EXPORT_STAGING_DIR created, writable by cinreadmd.

6. Software

rhel9-setup.sh installs these with dnf (RHEL9_SYSTEM_SETUP.md):

  • From RHEL's repositories: git, python3.14, python3.14-devel, python3.14-pip, gcc, gcc-c++, make, nginx, valkey, gettext, rsync, and glibc-langpack-en if needed.
  • From Microsoft's repository: unixODBC-devel, msodbcsql18.

rhel9-app-install.sh installs the Python packages into /rms/.venv.

8. Install and start

Step numbers refer to section 1 of RHEL9_QUICKSTART.md.

  1. Run rhel9-setup.sh (steps 1–2).
  2. Copy the code into /rms (steps 3–4).
  3. Write /rms/infra/.env (step 5).
  4. Run rhel9-app-install.sh (step 7).
  5. Write the nginx config (step 8).
  6. Start the app and check /api/health (section 3).
  7. Create the first admin (USER_PROVISIONING.md), then add the analysts.
  8. Load the cedant list (runbook on page 8).
  9. Give the server team the "After a server restart" steps in the runbook (C10).

9. Before production

  • C1: point MSSQL_LOSS_* at CIC's production loss repository.
  • C2: decide whether to use nginx, and fix it if so.
  • C3: set up HTTPS, or get CIC security's written acceptance of HTTP.
